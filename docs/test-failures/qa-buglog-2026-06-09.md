## BUG-001: Register form — inputs without name, method=GET
**Severity:** P2 (high)
**File:** `next/app/auth/register/page.tsx`
**Symptom:** Registration form has `method="get"` (default, no explicit method). Inputs have `id` but no `name` attributes. React `onSubmit` handler exists on `<form>` but bridge click triggers native HTML form submission (GET to same URL) instead of React handler. Form data not sent to API.
**Reproduction:**
1. Navigate to `/auth/register`
2. Fill Name, Email, Password, Confirm Password
3. Click "Create Account" button or call `<form>.requestSubmit()`
4. Page reloads via GET, returns "Invalid email format" error
**Expected:** POST to `/api/auth/register` with JSON body, user created
**Actual:** GET to `/auth/register` with no form data → shows "Invalid email format"
**Workaround:** API works via `curl -X POST /api/auth/register`

## BUG-005: Middleware redirects all routes including public
**Severity:** P2 (high)
**File:** `next/lib/middleware-utils.ts`
**Symptom:** Next.js middleware uses `PROTECTED_ROUTES` list checked via `startsWith()` pattern. Routes not in `PUBLIC_ROUTES` or `PROTECTED_ROUTES` (like `/api/health`, `/non-existent`) still trigger middleware redirect to `/auth/login` because the matcher catches all paths.
```
curl -s -w "%{http_code}" http://localhost:3000/api/health    → 307
curl -s -w "%{http_code}" http://localhost:3000/non-existent  → 307
```
**Expected:** `/api/health` → 200, `/non-existent` → 404
**Actual:** Both → 307 redirect to `/auth/login`

## BUG-007 (BLOCKER): Auth cookie not accepted by middleware
**Severity:** P1 (critical)
**Symptom:** `POST /api/auth/login` returns 200 with `Set-Cookie: token=eyJhbG...; HttpOnly; Path=/; SameSite=strict` but Next.js middleware always returns 307 redirect on subsequent requests with the cookie.
**Investigation:**
- JWT token decodes successfully: `{sub: "6583...", role: "admin", iat: ..., exp: ...}`
- Cookie sent correctly (confirmed via curl `-b/-c` jar, raw `-H "Cookie: token=..."`)
- `jsonwebtoken` library uses `process.nextTick` and other Node APIs NOT supported in Edge Runtime where middleware runs
- Build log warning: "A Node.js API is used (process.nextTick) which is not supported in the Edge Runtime"
- In dev mode middleware runs in Node.js but `verifyToken` still fails — possible env scope issue
- `process.env.JWT_SECRET` confirmed present in Next.js process (PID 66110 environ)
**Workaround for agent testing:** Access Pi Agent API directly on :4000 with `x-agent-api-key` header (but see BUG-012)

## BUG-010: Build fails — JWT_SECRET not available during build

## BUG-012: Pi Agent AGENT_API_KEY mismatch
**Severity:** P1 (critical) — BLOCKER for agent API
**Symptom:** Running Pi Agent processes reject the `x-agent-api-key` header even though the correct 64-char hex key from `.env` is sent. The process environment (`/proc/PID/environ`) shows `AGENT_API_KEY` line as only 29 bytes total, meaning the process has a ~14-char key — different from the 64-char key in `.env`.
**Check:**
```
.env:         AGENT_API_KEY=6d3f05...37fe  (64 hex chars)
/proc/.../environ: AGENT_API_KEY=???         (29 bytes total → ~14 char key)
```
**Fix needed:** Restart Pi Agent with current `.env` AGENT_API_KEY, or update `.env` to match running process.
